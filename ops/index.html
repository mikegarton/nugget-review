Nugget ops

Limits, channel economics, campaign yields, sources, tags, audio files, and knobs. Pick a section below; every table has filters, bounds, sort, a column chooser and an action cell (table-viewer v1). Save view keeps a table's filters, bounds, sort, columns and group under a name on this device; the View dropdown brings that table back with them; delete view removes the chosen one. Marked knobs are editable here with the ops write key; everything else is SQL-editor only.

Limits & burn

Each row names the resource being consumed and the consumer. Projected at reset = share of quota used ÷ share of the period elapsed — a straight-line projection of where the period ends. blue <50% · green 50–75% · yellow 75–90% · orange 90–100% · red ≥100%. Types: expires = prepaid allotment, unused value is lost at reset; ceiling = do-not-exceed cap; metered = pay-per-use judged against a chosen budget — nothing blocks at it. The database-size row has no growth history to project from, so it shows the share used now in the same five colors and has no tick. The tick on each bar marks where "exactly on pace" would be right now. A campaign and each of its phrases hold one of draft, active, stopped; a phrase is searched only while it and its campaign are both active. A campaign row's stop campaign sets the campaign to stopped and stops every active phrase of it with one shared stamp; its waiting videos are not processed while it is stopped. start campaign sets it to active and restarts exactly the phrases that stamp stopped (viewer headers show a stopped phrase as Stopped). The campaign sheet changes the same words.

Feed health — RSS fetch failures

One row per UTC day, from the hourly poller's sweep log (since 2026-09-28; before that a failed feed left no record). Feeds failed all day is the headline: feeds that failed in every sweep of the day, so no sweep read them; a feed that fails some hours and is read in others is a delay, not a loss (YouTube refused every channel feed between 22:00 and 07:00 UTC through 2026-10-19). A fetch is one channel's feed in one sweep. Failed = still failing after the one retry (10 s timeout, 2 s pause, no retry of a 404, see the parameters section); retry saved = failed once, fetched on the retry. Rescued by API = a YouTube feed that answered 404 and was read instead from the channel's uploads playlist through the YouTube API, one quota unit each (since 2026-10-25); it is not counted as failed. YouTube still refuses most channel feeds from about 00:00 to 07:00 UTC, so a full day shows about 150 to 170 of these. A full UTC day holds 24 sweeps, so a day with fewer sweeps lost a sweep entirely (the run was killed before it could log); today's row is partial. Feeds failed all day shows as yellow. The failing channels and their HTTP status are in yt_feed_sweeps.failures.

Campaign yield by query

Prime indicators first (nug/item · nug/$ · nug/kw — cost is every call cost of the videos that query found), then the funnel: found → screened out / promoted → processed → nuggets → your ratings. A query with finds but no ≥4★ after a couple of weeks is a candidate for stopping (the stop-phrase button on its headers in the viewer). Phrase status and campaign status are the words the database holds, draft, active or stopped; a phrase is searched only while both are active.

Sources — priority & economics

One integer per method of acquisition, lower = processed sooner, ties allowed; the queue tie-break is newest-published. Manual adds jump to priority 0 for the first 3 per hour. Priority is editable here with the ops write key (the priority button). Enabled says whether the source is read at all. Sources are subscribed or discovered — provenance, not quality; nuggets are rated on merit.

Category tags — coverage & TTL

Nuggets carry ordered category tags, primary first (since 2026-08-06; older nuggets show their legacy type instead). Primary is the tag in position one — the only tag counted where totals must equal sums, like cost attribution. Coverage = share of categorized nuggets carrying the tag in any position; because tags are multiple, coverage sums exceed 100% by design. A tag above ~60% coverage presumptively isn't earning its keep — unless it stratifies (rare on most sources, dominant on a few; filter on it in the viewer and see whether it separates channels). Human call, not a rule; the yellow figure is the flag. TTL is the tag's soft-expiry window: unrated nuggets outlive the longest TTL among their tags and drop out of "open" (rows kept — the viewer's Expired chip lists them; rating a nugget exempts it for good). TTL edits are SQL-editor only: update yt_categories set ttl_days = … where key = '…';

Channel economics — lifetime

Columns: identity, then prime value rates, then quality scores, then volume. Cost = Claude tokens + prorated Supadata credits, from the call log. Nugget counts are surviving nuggets. A channel is subscribed, not subscribed or blocked; its label carries the word when it is not subscribed. Channels not subscribed are campaign discoveries or manual-add hosts, not part of the subscribed poll list. A blocked channel is skipped by the poller, campaign discovery and the pending queue. Value rates are per-dollar — nug/$ and 5★/$ — because substack costs run magnitudes below video costs and "nuggets per dollar" compares cleanly where "$0.00003 per nugget" reads as noise; bigger is better, like every density column. nug/mo = surviving nuggets ÷ months since the channel's first processed item (denominator floored at 1 month, like views/day's 1-day floor). taste = the AI's guess at your interest (0–100); mentor = the AI's outside-expert value-per-time score (0–100); pk/med/avg = peak, median, average over surviving nuggets. hype (−5…+5) is per scored video, including zero-nugget ones. Substack transcript/minutes columns are legitimately blank; nug/item and nug/kw (nuggets per 1,000 words of transcript or post) are the density metrics both sources share — nug/kw counts only items processed since word counting began (2026-07-30), on both sides of the ratio. Channels processed before 2026-07-25 predate cost logging and show $0 (per-dollar rates blank). The ratios are computed in the database views since 2026-09-22. Subscribe appears on YouTube channels that are not subscribed; the two unsub buttons on subscribed channels: nuggets stops the feed, YouTube unsubscribes the account. Block (armed, with the ops write key) puts a channel in the blocked state from any other; unblock returns a blocked channel to not subscribed. cap/wk and priority are the channel's weekly cap and processing priority (✎ = editable here with the ops write key; empty clears); pending and stale are its waiting items and the items expired unprocessed.

Audio files

One row per content item that has rendered voice audio: a nugget's card, a post, or a video's transcript. Files = the mp3 pieces the item was cut into; length is hours:minutes:seconds, measured from the file's header when the render wrote it, est. from the character count at 15 characters a second for the files rendered before that. Created = the first piece's date; cost in dollars; queued by = the Audio list or the built playlist that asked for the item; played = an entry for it was played. Each row is one item in one voice, shown in voice (vendor.model.voice); an item rendered in two voices has two rows. play starts the row alone, in its own voice; play in table order plays the rows the table shows now, after filter, sort and group, one after another. The player bar at the foot of the page stays across sections: pause, next, stop. An item with no audio files is skipped and named in the bar. delete (armed, with the ops write key) removes the item's mp3 files, its render rows, its unplayed entries in the Audio list and the built playlists, and its A mark in the viewer.

Sift time

Sittings, newest first. One row per sitting: one unbroken run of viewer events on one device; a gap longer than sift_sitting_break_minutes starts the next sitting.
Sift time by source. One row per source and per campaign phrase, as peers.
Worked out from the tap log (one row per viewer event: every star tap, K, list button, card opened and closed, page hidden and shown, set loaded); nothing here is stored. Minutes sifted = the time between neighbouring events. Time with the page hidden counts zero. A stretch longer than sift_stretch_cap_seconds, and the open last stretch of a sitting, count as sift_fill_seconds and are shown again under filled: that part is a stand-in, not a measurement. Taps = presses on a star row, K or a list button. A stretch belongs to the item it ends on; the stretch after an item's last tap stays with that item until the next item's first tap or until the page is hidden, so reading a new item's title is credited one item back. The counts in the second table (rated at tier two and tier three, K, 5★ to 1–2★) are the last logged value per nugget since the tap log began, the same window as the minutes; ratings made before the log are not in them. Median tier-three = the middle length, in seconds, of the stretches spent with a card open, filled ones left out. The two per-hour columns are provisional best guesses, to be confirmed and tuned once 300 rating taps are logged.

Pipeline parameters — yt_params

Every live number the pipeline runs on, grouped by what it governs; the next run picks changes up, no redeploy. The bold name is the row's key — search the page or the code for it verbatim. Rows marked ✎ are editable here: click the value, enter the ops write key once per session (kept in this tab only, never stored). Bounds are enforced server-side — the browser is never trusted. Everything else stays SQL-editor only: update yt_params set value = '…' where key = '…'; Every change is audited.

Code constants — static, a change is a code release

Numbers fixed in the function source (and the one platform limit nothing can edit), listed here so every constant the pipeline runs on is findable by name in one place. The name is the identifier in the code. Change one by editing the named function and redeploying; this listing is maintained by hand alongside it (2026-09-11).
